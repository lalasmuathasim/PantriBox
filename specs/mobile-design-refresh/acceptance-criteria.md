# Mobile Design Refresh Acceptance Criteria

STATUS: ACTIVE

## Acceptance criteria

- The redesign is centralized in the mobile theme and shared-component layer.
- The legacy styling path remains preserved and easy to restore.
- The mobile app can switch between legacy and refreshed themes through a development-oriented mechanism without duplicating screen logic.
- No API contracts, domain models, or navigation flows are changed.
- Home, Lists, Scan, Insights, Profile, Sign In, and Sign Up reflect the new visual direction.
- Cards, spacing, typography, buttons, and bottom navigation feel cohesive and premium.
- Theme values are not hardcoded throughout feature screens when tokens or shared components should be used.
- Flutter format, analyze, and test pass after implementation.
- The app builds/runs in a simulator if the environment allows it.
